## How to ship a release
1. Bump `chesspuz.__version__` and `pyproject.toml`; tests + ruff; commit.
2. Windows zip, from PowerShell: `$env:PATH = "$PWD\.venv\Scripts;$env:PATH"; .\build_release.bat` (the PATH python is 3.12 without chess; Git Bash `cmd //c` cannot find the bat). Needs `%LOCALAPPDATA%\chesspuz\puzzles.sqlite` (or `CHESSPUZ_DB`). Output `dist\chesspuz-X.Y.Z-windows.zip`, about 81 MB. Smoke: `powershell -NoProfile -File tools\smoke_release.ps1 X.Y.Z` (fresh unzip in %TEMP%, empty data folder, offscreen; expects alive, user.sqlite created, no database copy, the bundled database locked by the app). It cannot tell a crash dialog from a running app.
3. APK: `.venv\Scripts\python.exe android\sync.py sync build --version X.Y.Z` (about two minutes; works from Bash too, also in the background). Commit first, or the build stamp (`android/app/mobile/build_info.py`, printed at startup in logcat) shows "+". `python android\sync.py install run` only with the phone on USB.
4. Screenshots if the UI changed: `python tools\release_shots.py docs\screenshots desktop` and `... phone`, look at them (the Read tool shows PNGs), commit.
5. Notes in `build\release-notes-X.Y.Z.md` (copy the previous page: `gh release view vPREV --json body -q .body`; hero image, download table, "New in", every feature with an image, phone trio, support link; images as `https://raw.githubusercontent.com/CARTER-BNW/chesspuz/main/docs/screenshots/...`; no em dashes). `git push` first (the images must be on main), then `gh release create vX.Y.Z --draft --target main --title "chesspuz X.Y.Z" --notes-file build\release-notes-X.Y.Z.md dist\...zip android\bin\...apk` with absolute paths; `gh release edit vX.Y.Z --draft=false --latest` publishes after John's check. While a draft, replace assets with `gh release upload --clobber` and notes with `gh release edit --notes-file` (each edit gives the draft a new untagged URL). The "Source code (zip/tar.gz)" links are GitHub's own and cannot be removed; the notes say so.
6. README PDF: `python tools\readme_pdf_source.py X.Y.Z "D Month YYYY"` writes `build\README-X.Y.Z.md` and copies the screenshots to `build\docs\screenshots`. Then from Git Bash in `build\`: `GSTACK_BROWSE_BIN="D:\\Claude\\config\\skills\\gstack\\browse\\dist\\browse" D:/Claude/config/skills/gstack/make-pdf/dist/pdf.exe generate --cover --no-confidential --author "John Carter" --title "chesspuz X.Y.Z" --date "..." README-X.Y.Z.md chesspuz-X.Y.Z-readme.pdf` (about 25 s; no `--toc`, its page numbers come out empty; `cd` back afterwards, the Bash tool's directory persists). Check the pages with PyMuPDF from the system Python 3.12 (installed with `--target` in the scratch dir of session a73d3ec9: `PYTHONPATH=<that>\pymupdf python`, `page.get_pixmap(dpi=60).save(...)`; reinstall with `python -m pip install --target <scratch>\pymupdf pymupdf` if that folder is gone). `gh release upload vX.Y.Z build\chesspuz-X.Y.Z-readme.pdf`.
7. Rewrite this file, tick docs/PLAN.md, commit, push.
